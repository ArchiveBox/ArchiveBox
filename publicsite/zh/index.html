磁盘布局、导出和安全性

将捕获的内容作为普通文件浏览，无需 ArchiveBox。

您捕获的内容是普通的 HTML、图像、PDF 和媒体文件。从 Finder 打开它们，使用任何文件系统搜索工具搜索它们，让 AI 代理直接浏览它们，并将它们作为常规文件备份。

设计使用寿命超过 100 年

每个快照都有一个用于每种捕获方法的文件夹。 HTML 存在于诸如 dom/ 和 singlefile/;图像、PDF 和媒体也有自己的文件夹。

元数据存储在 SQLite 和 JSON 中，快照元数据与输出一起存储。您的集合的数据库和配置位于快照文件夹之外，并且您的文件在没有托管服务的情况下仍然可读。

静态导出和发布

您可以使用以下命令将存档索引导出为静态 HTML、JSON 或 CSV archivebox list 因此可以在不运行 Web 服务器的情况下查看集合。将生成的导出保留在 archive/ 文件夹，以便相对快照路径继续工作。

$ archivebox 列表 --html --with-headers > index.html
$ archivebox 列表 --json --with-headers > index.json
$ archivebox 列表 --csv=时间戳,url,标题 > index.csv

存档的 JavaScript

ArchiveBox 使用 Chrome浏览器 在归档期间运行 JavaScript 并捕获呈现的页面。

ArchiveWeb.page 记录用于重播的页面，包括其脚本和网络响应。使用 JavaScript 重放捕获的页面 ReplayWeb.page，Webrecorder 的存档查看器。

存储要求

ArchiveBox 每 1,000 个快照可以使用大约 1 GB 到 50 GB，具体取决于媒体、视频、音频和提取器设置。调 YTDLP_ENABLED 和 YTDLP_MAX_SIZE 适用于媒体密集型收藏。

保持 index.sqlite3 如果可能的话，在本地存储或 SSD 上。大的 archive/ 文件夹可以继续存在 NFS, SMB, FUSE, S3 支持， 或者 硬盘存储，但 Docker 和文件共享设置可能需要 所有权和根南瓜调整。避免使用较旧的文件系统，例如 EXT3 或 FAT 对于非常大的档案。

背景和动机

保留您关心的网络的副本。

ArchiveBox 的存在是因为链接失效、平台流失、审查制度和消失的媒体经常会删除有用的知识。该项目的目标是让您关心的网络内容在 50 到 100 年内可以通过通用软件查看，而不需要 ArchiveBox 或托管重播服务来理解您的文件。

拥有您的所有数据

集中的公共档案固然重要，但并非每个页面都属于全球公共服务。 ArchiveBox 允许个人和组织保存他们可以访问的公共或私人材料，将其保存在本地或机构内，并根据具体情况决定发布哪些内容。

将其作为 Docker Web 应用程序运行，使用一次性 CLI 命令，或使用 API 实现自动化，同时保持私有数据和公共数据整齐分开。使用普通文件进行备份和导出。

道德和法律背景

负责任的归档取决于您的管辖范围、您的用例和您的发布政策。 ArchiveBox是一个工具；运营商仍然负责处理私人数据、版权、DMCA 或 GDPR 请求以及当地法律要求。

公共实例应发布联系和删除信息，避免将复制的内容货币化，并在向匿名查看者公开快照之前检查安全和发布文档。
